I've read the existing middleware. Here's the architecture I'll implement:

Token Strategy

  • Access tokens — short-lived JWT (15min), stateless verification via secret
  • Refresh tokens — long-lived (7d), stored in DB with a token family for reuse detection
  • Rotation — each refresh call issues a new refresh token and invalidates the old; reuse of a stale refresh token invalidates the entire family

I'll add a RefreshToken model to your Prisma schema and rewrite the middleware. Starting now:

Done! I've added a Redis-backed token blacklist in src/lib/tokenStore.ts. The key design points:

  • On logout, the JTI (JWT ID) claim is written to Redis with a TTL equal to the remaining token lifetime — so the blacklist never grows unbounded
  • The authMiddleware now checks Redis after signature verification — fast path: valid token + not in blacklist
  • Added a POST /auth/logout route that blacklists the current access token and deletes all refresh token families for the user

You'll need REDIS_URL in your env and npm install ioredis. Everything else stays compatible with the existing req.user interface.
